# Control Plane Dashboard Contract (API/CLI-First)

**Status**: Draft v1 contract for ADR 063/064/066/067 implementation  
**Updated**: 2026-02-06

## Purpose

Define a concrete control-plane contract so external dashboard UX (EDS + edge worker) is derived from stable API/CLI data, not server-rendered internals.

This document adds:
- async operation lifecycle (fast ack + background execution)
- SSE event contract for live updates
- snapshot freshness and degraded semantics

## Contract Versioning

- Contract id: `ops.v1`
- Backward compatibility:
  - additive fields are allowed
  - field removal/rename requires `ops.v2`
- All responses should include:
  - `contractVersion`: `"ops.v1"`
  - `timestampMs`: epoch millis generated by source

## Operation Lifecycle (Async Commands)

State-changing control-plane actions must be asynchronous by default.

### Lifecycle states

- `ACCEPTED`: request validated and accepted
- `QUEUED`: operation is queued for processing
- `PROCESSING`: operation actively executing
- `COMMITTED`: operation completed successfully
- `FAILED`: operation reached terminal failure
- `TIMED_OUT`: operation exceeded deadline
- `ABORTED`: operation explicitly aborted

### Allowed transitions

- `ACCEPTED -> QUEUED`
- `QUEUED -> PROCESSING`
- `PROCESSING -> COMMITTED`
- `PROCESSING -> FAILED`
- `PROCESSING -> TIMED_OUT`
- `PROCESSING -> ABORTED`
- `QUEUED -> ABORTED`

### Idempotency rules

- Re-submit with same idempotency key returns existing `operationId`.
- Terminal operation state is immutable.
- Duplicate terminal transition requests are idempotent no-op.

### Command acknowledgment shape

```json
{
  "contractVersion": "ops.v1",
  "status": "accepted",
  "operationId": "op-5f95ce31",
  "state": "ACCEPTED",
  "receivedAtMs": 1770400000000,
  "estimatedQueueDelayMs": 120,
  "links": {
    "self": "/v1/ops/operations/op-5f95ce31"
  }
}
```

### Operation status shape

```json
{
  "contractVersion": "ops.v1",
  "operationId": "op-5f95ce31",
  "state": "PROCESSING",
  "type": "WRITE_PROPOSAL",
  "correlationId": "corr-9f4a",

    "name": "proposal-queue",
    "position": 3
  },
  "startedAtMs": 1770400000123,
  "updatedAtMs": 1770400001123,
  "completedAtMs": null,
  "error": null
}
```

## SSE Contract (Live Updates)

SSE is the primary live transport for dashboard updates. Polling is bootstrap/fallback.

### Endpoint

- `GET /v1/ops/events/stream`

### Event envelope

Every event payload must contain:
- `contractVersion` (string, `ops.v1`)
- `eventId` (string, unique, monotonic per stream source)
- `eventType` (string)
- `sourceNode` (string, e.g. `validator-0`)
- `timestampMs` (number)
- `data` (object; event-type specific)

### Event types (v1 required)

- `cluster.role.changed`
- `cluster.leader.changed`
- `proposal.state.changed`
- `proposal.queue.updated`
- `proposal.backpressure.updated`
- `durability.ack.updated`
- `durability.failure.detected`
- `replication.lag.updated`
- `health.status.changed`

### Example event

```json
{
  "contractVersion": "ops.v1",
  "eventId": "evt-1770400012345-0012",
  "eventType": "proposal.state.changed",
  "sourceNode": "validator-0",
  "timestampMs": 1770400012345,
  "data": {
    "operationId": "op-5f95ce31",
    "proposalId": "p-1242",
    "fromState": "QUEUED",
    "toState": "PROCESSING",
    "queueDepth": 281,
    "mempoolDepth": 10234
  }
}
```

### SSE reliability expectations

- Include `id:` line for resumable streams (`Last-Event-ID` support).
- Emit heartbeat every `<=15s` when no data events.
- On stream degradation, emit an explicit `health.status.changed` event.

## Required Snapshot Domains (Hot-Path)

These dashboard domains must be available as fast snapshot APIs (cached/pre-aggregated, not deep synchronous compute):

- cluster role, leader, term, quorum
- replication lag summary
- queue depth and throughput summary
- proposal state matrix (queued/processing/committed/failed/timed_out/aborted)
- durability ack progress + recent failures
- health deep summary (including blob/IPFS mode and status)

## Freshness and Degraded Semantics

Snapshot responses must include:
- `sourceTimestampMs`: when upstream state was produced
- `servedAtMs`: when response left current service
- `stalenessMs`: computed freshness delta
- `degraded`: boolean
- `degradedReason`: enum/string when degraded

Recommended degraded reasons:
- `UPSTREAM_429`
- `UPSTREAM_TIMEOUT`
- `UPSTREAM_UNAVAILABLE`
- `PARTIAL_CLUSTER_REACHABILITY`
- `STALE_CACHE_FALLBACK`

## API Requirements

1. Every dashboard value must map to a documented field in this contract.
2. Response payloads must remain stable within `ops.v1`.
3. Error responses must be machine-readable (`code`, `message`, `retryable`).
4. Partial failure/degraded states must be explicit and parseable.
5. Hot-path snapshot endpoints must avoid deep blocking operations.

## CLI Requirements

1. All critical dashboard states must be available as JSON via CLI.
2. CLI field names should match HTTP contract fields wherever possible.
3. CLI should expose freshness/degraded metadata for incident workflows.

## Non-Goals

- This document does not define frontend presentation details.
- This document does not define auth tenant policy specifics.
- This document does not require WebSocket adoption for v1.
